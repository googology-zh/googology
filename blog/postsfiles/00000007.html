动态规划（四）：状压、轮廓线与插头

2026-11-21 · 编号 00000007

棋盘上的计数与最优性问题，状态往往是一张小集合。集合压进整数就是状压；集合信息只落在一条界线上时，只需要记住那条界线，这就是轮廓线；界线上的元素还要区分"谁和谁连着"，就是插头 DP。三者是同一件事的三层细化。

一、什么时候可以状压

两个条件：需要记住的集合规模可以枚举，一般不超过 $2^{20}$，实际题目多在 $2^{16}$ 以内；转移只依赖集合本身的局部信息，不依赖元素的排列或其他属性。前者决定内存，后者决定正确性。只要转移里出现"上一次选取的顺序"，这个压法就不成立，得把顺序也编码进去。

常见形式有三种：每行一个掩码，行内做合法性预处理（炮兵阵地、玉米田）；按位枚举子集，用 $3^n$ 表示"不选、选、被覆盖"三种状态；集合加当前点，即 TSP 的 $f_{S,i}$。第三种的状态数要乘上 $n$，估复杂度时别漏。

二、轮廓线：把行枚举改成格枚举

按行枚举时，一行有 $2^m$ 种状态，行内转移还要再枚举一次，代码通常写成两个掩码之间的匹配，长度一大就难写。轮廓线 DP 换一个视角：逐格决策，状态只记"已决策区域与未决策区域交界线"上的信息。界线长度仍是 $m$，信息量仍是 $2^m$，但转移变成每格 $O(1)$ 次，代码统一，也便于推广到连通性问题。

以 $n\times m$ 棋盘用 $1\times2$ 骨牌完全覆盖为例。状态 S 的第 $c$ 位表示"第 $c$ 列已被上一行竖放的骨牌占用"。

int n, m;
long long f[1 << 12], g[1 << 12];

// col: 当前列; S: 本行被上一行占用的列; nS: 下一行将被占用的列
void dfs(int col, int S, int nS, long long val, bool canDown) {
    if (col == m) { g[nS] += val; return; }
    if (S >> col & 1) { dfs(col + 1, S, nS, val, canDown); return; }
    if (canDown)                                  // 竖放
        dfs(col + 1, S, nS | (1 << col), val, canDown);
    if (col + 1 < m && !(S >> (col + 1) & 1))   // 横放
        dfs(col + 2, S, nS, val, canDown);
}

外层按行推进：

f[0] = 1;
for (int i = 0; i < n; ++i) {
    std::fill(g, g + (1 < m), 0);
    for (int S = 0; S < (1 < m); ++S)
        if (f[S]) dfs(0, S, 0, f[S], i + 1 < n);
    std::copy(g, g + (1 < m), f);
}
// 答案在 f[0]：最后一行处理完后不能再有向下占用

canDown 就是最后一行不能竖放这一条约束。少了它，程序会把骨牌铺到棋盘外，答案偏大，而这种错误在小数据上不一定暴露。

三、插头：连通性怎么记

回路、路径类问题里，状态不只是"格子是否被占"，还要知道"占用的格子属于哪个连通块"。界线上的每条边若与已决策区域相连，称为一个插头。一个连通块在界线上最多有两个插头（进入端与离开端），于是可以用括号序列表示：进入端记左括号，离开端记右括号。每位两个二进制位，0 表示无插头，1 表示左括号，2 表示右括号。

若一条路径可以多次经过同一连通块，括号表示就不够用了，需要最小表示法：把每个连通块在界线上的插头统一编号为当前最小编号，把同构状态消去。单回路问题用括号表示即可，多回路问题必须换最小表示。

四、四种转移

设格子 $(i,j)$ 处左插头为 $p$（界线第 $j$ 位）、上插头为 $q$（第 $j+1$ 位）。

情形含义操作
$p=q=0$新建连通块右插头记 1、下插头记 2，要求右侧与下方都有格子
$p\ne0,\ q=0$插头延伸向右或向下走，编码不变
$p=0,\ q\ne0$插头延伸向右或向下走，编码不变
$p=q=1$两个左括号相遇把 $q$ 匹配的右括号改成左括号
$p=q=2$两个右括号相遇把 $p$ 匹配的左括号改成右括号
$p=2,\ q=1$出口接入口两个插头同时消去，其余不动
$p=1,\ q=2$闭合回路仅在最后一格且界线已空时合法

完整实现如下。状态用哈希表滚动，网格无障碍，统计单回路条数。

int get(int S, int p) { return (S >> (p << 1)) & 3; }

void setp(int &S, int p, int v) {
    S = (S & ~(3 << (p << 1))) | (v << (p << 1));
}

void run(int i, int j, int S, long long val) {
    int p = get(S, j), q = get(S, j + 1);

    if (p == 0 && q == 0) {
        if (i + 1 < n && j + 1 < m) {
            int T = S; setp(T, j, 1); setp(T, j + 1, 2);
            g[T] += val;
        }
        return;
    }

    if (p && !q) {
        if (j + 1 < m) { int T = S; setp(T, j, 0); setp(T, j + 1, p); g[T] += val; }
        if (i + 1 < n) { g[S] += val; }     // 向下，插头留在第 j 位
        return;
    }

    if (!p && q) {
        if (j + 1 < m) { g[S] += val; }     // 向右，插头留在第 j+1 位
        if (i + 1 < n) { int T = S; setp(T, j, q); setp(T, j + 1, 0); g[T] += val; }
        return;
    }

    int T = S; setp(T, j, 0); setp(T, j + 1, 0);

    if (p == 1 && q == 1) {
        int bal = 1;
        for (int t = j + 2; t <= m; ++t) {
            int v = get(S, t);
            if (v == 1) ++bal;
            else if (v == 2 && --bal == 0) { setp(T, t, 1); break; }
        }
        g[T] += val;
    } else if (p == 2 && q == 2) {
        int bal = 1;
        for (int t = j - 1; t >= 0; --t) {
            int v = get(S, t);
            if (v == 2) ++bal;
            else if (v == 1 && --bal == 0) { setp(T, t, 2); break; }
        }
        g[T] += val;
    } else if (p == 2 && q == 1) {
        g[T] += val;
    } else {                                // p == 1 && q == 2
        if (i == n - 1 && j == m - 1 && T == 0) g[0] += val;
    }
}

主循环按格推进，行末左移两位，让上一行的向下插头移到下一行的上方位置：

std::unordered_map<int, long long> f, g;
f[0] = 1;
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < m; ++j) {
        g.clear();
        for (auto &kv : f) run(i, j, kv.first, kv.second);
        f.swap(g);
    }
    std::unordered_map<int, long long> h;
    for (auto &kv : f)
        if (get(kv.first, m) == 0) h[kv.first << 2] += kv.second;
    f.swap(h);
}
// 答案为 f[0]

行末那一步必须先检查第 $m$ 位为空，否则左移会把越界的插头带进下一行的第 $0$ 位，状态的含义就乱了。i、j 的类型是 int，(p << 1) 即 p * 2，别写成移位以外的花样。

五、复杂度与常见坑

  • 状态数上界 $4^{m+1}$，实际远小于此，$m\le 12$ 时通常只有几千到几万。$m$ 超过 14 基本不可做。
  • 闭合回路的判定要严：T == 0 与最后一格两个条件缺一不可，否则会把多条回路拼成一条，或把断开的路径当成回路。
  • 网格有障碍时，障碍格上不允许任何插头通过，且 $p,q$ 必须同时为 0；转移前先判这一条。
  • 手写开放寻址散列比 std::unordered_map 稳，后者在状态数上万时 rehash 的常数很难估。真要省事，先用 unordered_map 写对，再换实现。
  • 方案数用 long long，取模的题按题意取；滚动表的清空只清有效位，不要每次 memset 整个 $4^{m+1}$ 大小的数组。

建议的练习顺序：先写骨牌覆盖，把轮廓线的移位和行末处理弄熟；再把状态换成三进制括号，写单回路；最后加障碍、加多条路径。每一步都用小规模暴力对拍，插头 DP 的错误几乎都藏在转移的那几种情况里。

数位、树形、期望方程与矩阵递推这几种展开方式，见第五篇。
