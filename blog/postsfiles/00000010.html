树链剖分：重链、DFS 序与路径查询

2026-11-21 · 编号 00000010

树上的路径查询要落到线段树上做，前提是把路径拆成若干段连续区间。树链剖分给出的拆法是：沿"重儿子"一路走成链，每条链在 DFS 序里是连续一段，任意路径只跨越 $O(\log n)$ 条链。预处理 $O(n)$，一次路径查询 $O(\log^2 n)$。

一、重儿子与轻边

对每个点 $u$，在它的儿子中取子树最大的那个，称为重儿子；连向重儿子的边叫重边，其余叫轻边。从 $u$ 出发沿重边一路向下，得到一条重链，链与链之间由轻边相连。

关键性质：轻边 $(u,v)$ 满足 $siz_v\le \dfrac{siz_u}{2}$。因为 $v$ 不是最大的儿子，就存在另一个儿子 $w$ 满足 $siz_w\ge siz_v$，于是 $siz_u\ge 1+siz_v+siz_w\ge 1+2\,siz_v$。所以从任意点向上走到根，经过的轻边不超过 $O(\log n)$ 条，跨越的重链也不超过这个数。路径查询的复杂度就来自这里。

二、两遍 DFS

第一遍求子树大小与重儿子；第二遍分配 DFS 序，并让重儿子紧跟在父亲之后，保证同一条链在序上连续、同一棵子树在序上连续。

int siz[MAXN], son[MAXN], fa[MAXN], dep[MAXN];
int dfn[MAXN], top[MAXN], rk[MAXN], timer;

void dfs1(int u, int f) {
    siz[u] = 1; son[u] = 0; fa[u] = f; dep[u] = dep[f] + 1;
    for (int v : g[u]) {
        if (v == f) continue;
        dfs1(v, u);
        siz[u] += siz[v];
        if (siz[v] > siz[son[u]]) son[u] = v;
    }
}

void dfs2(int u, int t) {
    top[u] = t;
    dfn[u] = ++timer;
    rk[timer] = u;
    if (son[u]) dfs2(son[u], t);                  // 重儿子继承链头
    for (int v : g[u])
        if (v != fa[u] && v != son[u]) dfs2(v, v); // 轻儿子自立链头
}

siz[0]=0 使叶子的 son 为 0，不必特判。rk 是 DFS 序到点号的映射，建树时按 rk 取点权。递归深度等于树高，链状数据下 $n$ 上万就可能爆栈，改成手写栈或调大栈空间。

三、路径查询

两端不在同一条链上时，把链头更深的那一端整段查掉，再跳到链头的父亲；直到同链，查剩余一段。每一轮至少上移一条链，轮数 $O(\log n)$，每轮一次线段树查询，合计 $O(\log^2 n)$。

long long pathQuery(int u, int v) {
    long long s = 0;
    while (top[u] != top[v]) {
        if (dep[top[u]] < dep[top[v]]) std::swap(u, v);
        s += query(1, 1, n, dfn[top[u]], dfn[u]);
        u = fa[top[u]];
    }
    if (dep[u] > dep[v]) std::swap(u, v);
    s += query(1, 1, n, dfn[u], dfn[v]);
    return s;
}

比较的是 top 的深度，不是 u 与 v 的深度。写成后者时多数数据仍能过，只在链头深度关系特殊时出错，属于"看着像对的"那一类。最后同链的一段要先交换，使 u 更浅，区间才是 [dfn[u], dfn[v]]。

子树查询更简单：子树在 DFS 序里是 [dfn[u], dfn[u]+siz[u]-1]，一次线段树操作，$O(\log n)$。路径修改与查询同构，把 query 换成带懒标记的 modify。

四、边权与点权

题给的是边权时，把每条边的权下放到深度较大的端点，路径查询的中间段不变，但最后同链的一段要去掉 LCA 那个点：查询区间改成 [dfn[u]+1, dfn[v]]，其中 u 是较浅的 LCA。这一步漏掉，会把 LCA 上方的边权算进来。

反过来，点权转边权（例如查询路径上的点权和但不含两端）也常用类似处理，写之前先明确"端点算不算"，再决定区间是否加减一。

五、与其他结构的配合

  • 线段树维护区间和、区间最值、区间加、区间赋值，按题目选用；树剖只负责把路径变成区间，不决定线段树维护什么。
  • LCA 可以直接用树剖求：跳链到同一条后，浅的那个就是 LCA，常数小于倍增。
  • 需要子树整体加、路径求和时，树剖加线段树是标准组合，$O(\log^2 n)$。
  • Link-Cut Tree 把"链"改成动态维护的 splay，支持加边删边，复杂度均摊 $O(\log n)$，但常数与实现难度都高出一截。树形态固定时，没有必要上 LCT。

六、常见错误

一是 dfn 与点号混用：建树、查询里所有下标都必须是 DFS 序，取权值要经过 rk。二是重儿子为空时仍去 dfs2(son[u], ...)，访问到 0 号点。三是多组数据忘记清空 timer、head 与线段树数组。四是把 top 的初值写成 0，跳链时得到 fa[0]，答案随机偏移。

验证方式：随机小树，路径查询与"逐点向上累加"对拍；子树查询与"枚举所有后代"对拍。树剖的边界问题基本都在这两项里暴露。
