TypeScript 进阶：类型运算与工程配置

2026-11-21 · 编号 00000028

进阶部分讲类型层面的运算：映射类型、条件类型与 infer、工具类型的来源、声明合并与模块扩充、类型守卫，最后是工程配置。这些内容的目标不是炫技，是把重复的类型推导压到一处。

一、keyof 与映射类型

type Keys = keyof User;                       // "id" | "name" | "tags"

type OptionalUser = { [K in keyof User]?: User[K] };

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

映射类型遍历键的联合，as 子句可以重映射键名。这里要写 string & K 是因为 keyof 可能含 number 或 symbol 键，而模板字面量类型只接受字符串。

直接写成 [K in keyof T] 的同态映射会保留原属性的可选、只读修饰符；用 Record<string, T> 之类手写则会把修饰符丢掉。需要精细控制时可以加 +?、-?、-readonly。

二、条件类型与 infer

type Elem<T> = T extends (infer U)[] ? U : never;
type Ret<T> = T extends (...args: any[]) => infer R ? R : never;
type Unwrap<T> = T extends Promise<infer U> ? Unwrap<U> : T;
type NotDist<T> = [T] extends [string] ? 1 : 0;

条件类型的左侧是裸类型参数时会发生分发：传入联合类型，会逐支计算再合并结果。[T] extends [U] 把它包进元组，阻止分发。never 在分发时直接得到 never，这是一个常见意外。

infer 在条件里声明一个待推断的类型变量，同一分支多次出现时结果取交集。递归类型必须有终止分支，否则编译器报深度超限；Unwrap 这类写法在深层嵌套时容易触顶。

三、工具类型

Partial、Required、Readonly 是映射类型加修饰符；Pick、Omit 从键集合里取子集；Record 构造键值映射；Exclude、Extract、NonNullable 在联合上做过滤；Parameters、ReturnType、InstanceType、Awaited 从函数与 Promise 里取类型。

这些类型全部由映射与条件类型组合而成，看懂实现之后，遇到不满足需求的场景直接按同样思路写一个，比去找第三方类型库快。注意 Omit 不做键的存在性检查，传入不存在的键不会报错，需要严格检查时自己写一个约束。

四、声明与模块扩充

declare const VERSION: string;

declare global {
  interface Window { app: App }
}

export {};

.d.ts 只声明不实现，编译后不产生代码。declare module 给没有类型的第三方库补形状；declare global 扩充全局，但文件必须先是模块（有 export 或 import），否则会直接污染全局，兜底加一行 export {}。

给库补类型时优先用上游自带的类型，其次找 @types/包名，最后才自己写在 types.d.ts 里。自己声明的形状与真实实现不一致时，编译通过但运行报错，这类问题最难定位。

五、类型守卫与断言函数

function isString(x: unknown): x is string {
  return typeof x === "string";
}

function assertDefined<T>(x: T | undefined): asserts x is T {
  if (x === undefined) throw new Error("undefined value");
}

谓词函数的返回类型写成 x is T，调用处就能收窄。asserts x is T 是断言签名：调用之后若没有抛出，编译器按 T 处理后续代码。断言函数必须有显式返回类型，写成箭头函数也要单独标注。

守卫函数内部不要用 as 绕过检查，那等于把错误挪到别处。复杂结构的校验优先用运行时校验库（如 zod），从 schema 反推类型，比手写守卫更不容易漂移。

六、工程配置

strict 必开；noUncheckedIndexedAccess 让下标访问带上 undefined，能拦住越界；exactOptionalPropertyTypes 区分“没写”与“写了 undefined”；isolatedModules 保证单文件转译可行，Babel、esbuild、SWC 都要求它。

paths 里的别名只影响类型解析与 tsc 输出，打包器要另配 alias 才能运行时生效；declaration 生成 .d.ts，skipLibCheck 跳过依赖库的检查提速度；incremental 缓存上次结果，大项目编译时间能明显下降。

七、易错点

  • 条件类型忘了分发规则，联合类型算出不符合预期的结果。
  • 递归类型没有终止分支，编译器报类型实例化过深。
  • 以为 Omit 会检查键是否存在。
  • declare global 写在非模块文件里，污染全局作用域。
  • 断言函数的返回类型漏写，调用处没有任何收窄。
  • paths 配了别名，运行时找不到模块。
