动态规划（一）：状态的闭合与转移的次序

2026-11-18 · 编号 00000004

动态规划的难点几乎都在建模。方程列出来之后，实现只是照着下标填表。建模要回答两个问题：状态取什么，转移按什么次序展开。前者决定正确性，后者决定能不能递推。

一、状态是部分解的等价类

一个状态，实际上是一批部分解的合并。判断两个部分解能否合并，只看一件事：它们对尚未处理的部分是否产生相同的影响。若相同，后续的决策与收益就只由当前状态决定，与怎样到达这里无关；这时状态是闭合的，也叫满足无后效性。

最容易犯的错误是把"已经得到的最优值"直接当作状态，却漏掉转移时需要查询的量。以最长上升子序列为例，$f_i$ 记"以 $a_i$ 结尾的最长长度"是闭合的，因为下一步只需要知道末项的值；若写成"前 $i$ 个数中的最长上升子序列长度"，末项被丢掉了，下一个数能否接上无从判断，这个状态就不能用。

由此得到一条实用的做法：先按最朴素的方式写转移，看转移式里用到了历史的哪些量，把这些量补进下标；补完之后若仍有若干情形结果完全相同，再合并。多一维是拿空间换正确性，少一维是拿正确性换空间，取舍由数据范围决定。

二、转移要沿 DAG 走

状态之间的转移关系若无环，按拓扑序递推即可。出现环，通常说明状态没有把"阶段"划清：区间 DP 把环化为"最后一次操作"，图上的问题先缩点再在 DAG 上做，都是同一个思路。记忆化搜索是在运行时确定次序，递归调用关系天然给出拓扑序，不必事先排序。

两种写法各有适用面。递推没有函数调用和查表的开销，适合下标连续、状态稠密的情形；记忆化只访问可达状态，适合状态稀疏或维数高、上界估不准的情形。同一道题，两种写法的实际耗时可以差一个量级。

转移的枚举范围要按不重不漏来设计。以区间 DP 为例，枚举断点 $k$ 表示最后一次合并的位置，左右子区间互不重叠，每条方案恰好被数一次。

三、常见的四种骨架

  • 线性 DP：按位置或前缀推进，状态里带一个"处理到哪"的下标。
  • 背包：状态是容量，物品在外层。0-1 背包的容量必须倒序枚举，完全背包正序，多重背包按二进制拆分。
  • 区间 DP：按区间长度从小到大枚举，长区间由短区间拼出；环形问题把序列接到长度 $2n$ 上，再截取长为 $n$ 的答案。
  • 树上 DP：后序 DFS，把子节点的结果合并进父节点；带依赖的背包型合并要注意循环顺序与容量上界，合并代价是两侧容量上界之积。

四、0-1 背包的滚动数组

设物品 $i$ 的体积为 $w_i$、价值为 $v_i$，容量上限为 $V$。用 $f_j$ 表示容量不超过 $j$ 时的最大价值，初值全为 $0$。

for (int i = 1; i <= n; ++i)
    for (int j = V; j >= w[i]; --j)
        f[j] = max(f[j], f[j - w[i]] + v[i]);

容量倒序枚举是关键：计算 $f_j$ 时用到的 $f_{j-w_i}$ 必须仍是"没有考虑第 $i$ 件物品"的旧值。正序枚举会让同一件物品被重复选取，那正是不限件数的完全背包。复杂度 $O(nV)$，空间 $O(V)$。

当 $V$ 达到 $10^9$ 而 $n$ 只有几十时，这个复杂度不可接受。此时或者按价值维度做，用 $g_v$ 记达到价值 $v$ 所需的最小体积；或者折半枚举：把物品分成两半，各自枚举子集，排序后用双指针合并。

五、区间 DP 的最后一步

石子合并一类的题写出来是 $f_{l,r}=\min_{l\le k<r}\left(f_{l,k}+f_{k+1,r}\right)+s_r-s_{l-1}$，其中 $s$ 为前缀和，第三项是本次合并的代价。

for (int len = 2; len <= n; ++len)
    for (int l = 1, r = len; r <= n; ++l, ++r) {
        f[l][r] = INF;
        for (int k = l; k < r; ++k)
            f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r]);
        f[l][r] += s[r] - s[l - 1];
    }

直接做的复杂度是 $O(n^3)$。$n$ 上千时需要用四边形不等式把断点的枚举范围压到均摊常数，这是下一篇的内容。

六、先估复杂度，再动手写

复杂度等于状态数乘以单个状态的转移代价。状态数由各维上界相乘得到，转移代价就是循环层数。这个乘积超过 $10^8$ 时，先考虑换维度、换枚举方式，而不是靠常数优化硬扛。实现细节上，下标尽量连续，避免在转移内部做哈希查找；能开成定长数组的就不要用 std::map。
