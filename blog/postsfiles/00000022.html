Python 进阶：生成器、装饰器与并发

2026-11-21 · 编号 00000022

进阶部分集中在这几处：惰性求值的生成器、装饰器、上下文管理器、类型标注与 dataclass、并发模型、以及“先测量再优化”的做法。这些内容共同指向一件事——让代码在规模变大后仍然可控。

一、推导式与生成器

推导式是循环的表达式形式，生成器把“算一个取一个”写成函数。它们的共同点是惰性：不取就不算，因此可以表示无限序列，也可以把大文件的处理压到常数内存。

squares = [x * x for x in range(10) if x % 2]
gen = (x * x for x in range(10))      # 生成器表达式

def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()

import itertools
itertools.islice(read_lines("a.txt"), 5)

生成器只能遍历一次，第二次拿到空序列；需要重复使用就先转成列表。代码块里的 itertools.groupby 只对相邻的同键元素分组，数据没排序时会得到一堆碎组，正确用法是先 sorted(key=...) 再分组。

二、装饰器

import functools, time

def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        t = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(fn.__name__, "%.3fs" % (time.perf_counter() - t))
    return wrapper

@timed
def work(n):
    return sum(range(n))

不加 functools.wraps，包装函数的 __name__、__doc__、__wrapped__ 都会丢，调试和框架反射会出错。带参数的装饰器是三层函数：最外层收参数，中间层收函数，内层收调用参数。

装饰顺序按从下往上应用：@a @b def f 等价于 a(b(f))。多个装饰器叠加时，最先执行的是最靠近函数定义的那个。类也可以被装饰，只要它实现 __call__，这种写法适合需要保存实例状态的场景。

三、上下文管理器

from contextlib import contextmanager
import os

@contextmanager
def chdir(path):
    old = os.getcwd()
    os.chdir(path)
    try:
        yield
    finally:
        os.chdir(old)

类写法实现 __enter__ 与 __exit__，__exit__ 返回真值会吞掉异常——除非确实要抑制，返回 False 或 None。生成器写法必须把 yield 放进 try/finally，否则异常时清理代码不执行。

四、类型标注与 dataclass

from dataclasses import dataclass, field
from typing import Optional

@dataclass(frozen=True)
class Node:
    value: int
    children: list["Node"] = field(default_factory=list)
    note: Optional[str] = None

标注不参与运行检查，它只是给 mypy、pyright 和编辑器看的。想真正拦住类型错误，要在 CI 里跑一次类型检查。list["Node"] 里的引号是前向引用，类还没定义完时用它避免 NameError。

dataclass 的默认值必须用 default_factory，直接写 [] 会被所有实例共享；frozen=True 生成 __hash__，可以作字典键；eq、order 控制比较行为。字段顺序决定 __init__ 的参数顺序，有默认值的字段必须排在后面。

五、三种并发模型

GIL 保证同一时刻只有一个线程执行字节码，所以 threading 对 CPU 密集任务没有加速效果；它适合等待 IO 的场合。multiprocessing 用进程绕开 GIL，代价是数据要序列化传递。asyncio 用单线程加事件循环，在大量并发连接时才划算。

import asyncio

async def fetch(i):
    await asyncio.sleep(0.1)
    return i

async def main():
    return await asyncio.gather(*(fetch(i) for i in range(5)))

result = asyncio.run(main())

协程里调用同步阻塞函数（requests、time.sleep）会阻塞整个事件循环，等于把并发退化成串行；要么换异步库，要么用 loop.run_in_executor 丢到线程池。asyncio.run 只能在最外层调用一次，嵌套使用会报错。

六、性能与内存

优化前先测量：timeit 比较短代码片段，cProfile 找函数级热点，tracemalloc 看内存分配。凭直觉改代码，多数时候改的不是瓶颈。

常见有效手段：用 __slots__ 去掉实例的 __dict__，大量小对象时能省不少内存；用 array、struct 处理同质数值序列；用生成器降低峰值内存；用 bisect、heapq 替代手写查找。

七、易错点

  • 生成器第二次遍历为空，误以为数据丢了。
  • 装饰器顺序写反，lru_cache 套在计时外面导致缓存失效判断出错。
  • dataclass 用可变默认值，所有实例共享同一个列表。
  • 在 finally 里 return，异常被悄悄吞掉。
  • 在事件循环里跑阻塞调用，并发名存实亡。
  • asyncio.create_task 创建的任务没有被 await，异常只在回收时才冒出来。
