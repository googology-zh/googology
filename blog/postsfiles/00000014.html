C++ 模板元编程（一）：类型、常量与 SFINAE

2026-11-21 · 编号 00000014

模板元编程（template metaprogramming，下文简称 TMP）指的是把类型和整型常量当作计算对象，在编译期完成选择与计算。它不是语法炫技：真正有用的部分只有两块，一是让编译器替你挑对重载或特化，二是把能在编译期算出的常量提前算掉。代价同样明确——编译时间、实例化数量，以及一旦出错就难以阅读的诊断信息。

本文假定读者已经会用函数模板和类模板，知道偏特化与可变参数模板的基本写法。涉及的标准以 C++17 为准，C++20 的 concepts 只作对照提及。

一、实例化与两阶段名字查找

模板不是文本替换。编译器在解析模板定义时只检查与模板参数无关的名字，这称为第一阶段；模板被实例化时，才检查依赖于模板参数的名字，这是第二阶段。由此产生两个后果。

其一，定义里出现的 T::value_type 这类依赖类型必须加 typename，否则编译器无法判断它是类型还是静态成员：

template <class T>
typename T::value_type first(const T &c) {
    return *c.begin();
}

其二，依赖模板名后跟 < 时要加 template 消歧，典型出现在成员模板上：

template <class Alloc>
struct Pool {
    template <class U> struct Rebind { using type = Pool<typename Alloc::template rebind<U>::other>; };
};

漏掉这两个关键字时报错位置往往指向一个看似无关的行，因为解析器已经把 < 当成了小于号。

二、把常量放进类型

类模板的参数可以是类型、整型常量、指针或引用（后两者在 C++17 起对非类型模板参数限制放宽），也可以是模板本身。整型常量进入类型系统后，就能参与编译期计算。最小的例子是阶乘：

template <int N>
struct Fact {
    static constexpr long long value = N * Fact<N - 1>::value;
};

template <>
struct Fact<0> { static constexpr long long value = 1; };

static_assert(Fact<10>::value == 3628800);

主模板负责递推，Fact<0> 的显式特化负责终止。static_assert 让这条计算在编译期就被检查，写错了不会有运行期才发现的机会。斐波那契同理，只是需要两个终止特化：

template <int N>
struct Fib {
    static constexpr long long value = Fib<N - 1>::value + Fib<N - 2>::value;
};
template <> struct Fib<0> { static constexpr long long value = 0; };
template <> struct Fib<1> { static constexpr long long value = 1; };

这种写法在 C++11 之后已经不是首选。同样的计算用 constexpr 函数即可完成，语法更接近普通代码：

constexpr long long fact(int n) { return n == 0 ? 1 : n * fact(n - 1); }
static_assert(fact(10) == 3628800);

模板递归真正的用途不在算数，而在需要"常量出现在类型里"的场合：数组维度、模板参数、std::integral_constant 的标签。比如一个编译期判断质数的变量模板：

template <int N, int D>
struct IsPrimeImpl {
    static constexpr bool value = (N % D != 0) && IsPrimeImpl<N, D - 1>::value;
};
template <int N>
struct IsPrimeImpl<N, 1> { static constexpr bool value = true; };

template <int N>
constexpr bool is_prime_v = (N >= 2) && IsPrimeImpl<N, (N > 2 ? N - 1 : 1)>::value;

static_assert(is_prime_v<97>);
static_assert(!is_prime_v<91>);

变量模板 C++14 起可用。N > 2 ? N - 1 : 1 这个条件不能省，否则 N = 2 时 IsPrimeImpl<2, 1> 没问题，但 N = 1 会实例化 IsPrimeImpl<1, 0>，D 递减到 0 时除以零，直接编译失败。

三、SFINAE：替换失败不是错误

SFINAE 是 substitution failure is not an error 的缩写：模板参数替换阶段产生的失败，只会让这个候选从重载集中移除，而不是立刻报错。这条规则是编译期"按条件选择重载"的基础。

关键在于替换失败与实例化失败的界限。函数返回类型、模板参数类型、默认模板参数里的表达式属于替换阶段；函数体、类模板的成员定义属于实例化阶段。后者出错是硬错误，不会被静默移除。

检测某个类型有没有成员函数 begin，可以用 void_t：

template <class, class = void>
struct has_begin : std::false_type {};

template <class T>
struct has_begin<T, std::void_t<decltype(std::declval<T>().begin())>>
    : std::true_type {};

第二个模板参数默认是 void。若 decltype(...) 合法，void_t 把它折叠成 void，偏特化匹配，得到 true_type；若不合法，偏特化在替换阶段失败被丢弃，回落到主模板的 false_type。C++17 之前要手写 template<class...> using void_t = void;，标准库版本对未使用的参数有额外处理，自己写的那版在旧编译器上偶有失效。

用 enable_if 按条件选择重载，最稳妥的位置是返回类型或模板参数的类型，而不是默认值：

template <class T>
std::enable_if_t<std::is_integral_v<T>, T> twice(T x) { return T(x + x); }

template <class T>
std::enable_if_t<std::is_floating_point_v<T>, T> twice(T x) { return T(x * 2); }

两条声明在返回类型上不同，替换失败的那条会被移除，调用 twice(3) 与 twice(1.5) 各自命中一条。若把 enable_if 写成 template <class T, std::enable_if_t<...> = 0> 的形式，两个只差默认模板实参的函数模板会被视为同一签名，产生重定义错误。

C++17 的 if constexpr 能替代一部分 SFINAE。它在函数体内按常量条件丢弃分支，未选中的分支不参与实例化，于是"某个类型没有这个成员就换个写法"可以写在同一函数里，不必再造一个重载。区别是 if constexpr 只能用于函数体内部，无法改变函数的签名，也无法让一个声明在重载集中消失。

四、成本与边界

  • 每个不同的模板实参组合都会产生一份独立实例化。类型列表稍长，实例化数量就按组合爆炸，编译时间与目标文件体积同时上涨。
  • 模板递归有深度上限，GCC 默认 -ftemplate-depth=900，陡峭的线性递归很容易撞上；改成按二分的递归可以把深度降到对数级。
  • 出错信息里模板栈通常有几十层，定位要看最内层的 static_assert 或类型不匹配处，不要从第一行读起。
  • 能用 constexpr 函数或 if constexpr 表达的逻辑，不要用类型递归。前者编译更快，诊断更清楚。
