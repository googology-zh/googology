可持久化线段树：区间第 k 小与版本回溯

2026-11-21 · 编号 00000011

可持久化的意思不是"把每个版本都存一份"，而是"修改时不破坏旧版本"：只复制从根到被修改叶子的那条路径，其余节点由新旧版本共享。一次单点修改新增 $O(\log n)$ 个节点，于是所有历史版本可以同时存在。

一、区间第 $k$ 小

对序列建前缀版本的权值线段树：root[i] 是插入 $a_1,\dots,a_i$ 之后的树。查询 $[l,r]$ 的第 $k$ 小，就把 root[r] 与 root[l-1] 一起从根往下走：左子树里实际落入区间的数的个数，等于两个版本左子树计数之差；若这个差大于等于 $k$，答案在左子树，否则在右子树、$k$ 减去该差。

int ls[MAXN * 20], rs[MAXN * 20], cnt[MAXN * 20], root[MAXN], tot;

int update(int p, int l, int r, int x) {
    int q = ++tot;
    ls[q] = ls[p]; rs[q] = rs[p]; cnt[q] = cnt[p] + 1;
    if (l == r) return q;
    int mid = (l + r) >> 1;
    if (x <= mid) ls[q] = update(ls[p], l, mid, x);
    else          rs[q] = update(rs[p], mid + 1, r, x);
    return q;
}

// 在 (root[l-1], root[r]] 中找第 k 小，值域为 [l, r] 的离散化下标
int kth(int u, int v, int l, int r, int k) {
    if (l == r) return l;
    int mid = (l + r) >> 1;
    int leftCnt = cnt[ls[v]] - cnt[ls[u]];
    if (k <= leftCnt) return kth(ls[u], ls[v], l, mid, k);
    return kth(rs[u], rs[v], mid + 1, r, k - leftCnt);
}

节点 0 是一棵空树，ls[0]=rs[0]=cnt[0]=0，于是 root[0]=0 可以直接作为起点，不必单独写建树函数。数组大小按 $(n+m)\log n$ 开，$n=m=10^5$ 时约 $3.6\times10^6$，开 20 倍容易不够，实际要按修改次数的上界乘。

值域要先离散化：第 $k$ 小返回的是下标，输出时需要映射回原值。若值域很大又不想离散化，把动态开点与可持久化一起用，节点数仍是 $O((n+m)\log V)$。

二、单点修改与版本回溯

从一个版本 root[t] 出发做修改，返回新的根，旧根不动。这就是"可持久化数组"：每次修改产生一个新版本，查询某个版本某个位置的值时，沿路径走到叶子即可，$O(\log n)$。

要注意共享节点的不可变性：任何一次修改都不能原地改动 cnt 或子指针，否则旧版本跟着变，整套结构失效。上面的 update 先复制再递归，正是为此。

三、树上的第 $k$ 小

把前缀版本搬到树上：root[u] 表示从根到 $u$ 路径上的权值线段树，由父亲的版本插入 $val_u$ 得到。查询 $u$ 到 $v$ 路径上的第 $k$ 小，用四个根做差：

$$cnt=cnt_{root_u}+cnt_{root_v}-cnt_{root_{lca}}-cnt_{root_{fa(lca)}}$$

这样每条路径的查询是 $O(\log n)$，建树是 $O(n\log n)$。同一套"四根做差"还能处理路径上某值的出现次数。树剖加主席树也能做，但常数更大，除非还要支持修改。

四、可持久化并查集

把并查集的父亲数组做成可持久化数组，每次合并产生新版本，就得到可持久化并查集。两条限制：不能路径压缩（压缩会改动大量节点，每次操作退化成 $O(n)$），只能按秩或按大小合并；查询时沿父亲链走到根，$O(\log n)$。于是单次操作 $O(\log^2 n)$，空间同样 $O(m\log n)$。

这类题的价值在于"回到某个历史时刻"，例如按时间加边、查询某时刻两点是否连通。若只需要离线回答，用分治加可回滚并查集（按秩合并 + 栈记录）更省空间，不必上可持久化。

五、可持久化 trie

同样是前缀版本，把权值线段树换成二进制 trie，就能查询区间内与给定数异或的最大值：从高位往下走，优先选择与当前位相反的分支，用两个版本的计数差判断该分支在区间内是否存在。位数为 30 时每次查询 $O(30)$，比线段树常数更小。

六、复杂度与易错点

  • 节点数上界是"修改次数 $\times(\log_2 V+1)$"，修改次数包括建前缀版本与后续更新，不要只按 $n$ 估。
  • kth 的递归区间与离散化后的下标必须一致，混用原值与排名是最常见的错误。
  • 树上的版本共用同一套节点池，四根做差时下标不能重复使用同一棵树两次。
  • 可持久化并查集不要写路径压缩，也不要按"深度"合并后忘记更新深度。
  • 多组询问时，tot 归零即可复用节点池，但旧的根必须一并清零，否则会访问到上一组数据的节点。

验证方式：随机序列，区间第 $k$ 小与"截取子数组排序"对拍；树上版本与"路径逐点收集后排序"对拍。可持久化结构的错误几乎都是"少复制了一个节点"或"混用了新旧根"，对拍十组就能发现。
